Two rules that overlap — and how the scanner decides

r matches both REST and ID. riff matches ID (4 characters) and REST (1 character), so maximal munch chooses ID. A bare r matches both with length 1, so rule priority chooses REST, because REST is listed first. That is the whole tie-breaking policy of Lex, implemented here in ten lines.

The first draft of the grammar was ambiguous — here is the diagnosis

Sequencing was originally written comp -> comp comp, and a chord (D4 F4 A4)/2 was written with the same brackets as a group (...). Module 3 — Semantic analysis (L-attributed SDD)

Six attributes are inherited (passed down the tree) and three are synthesised (passed up). Cadence needs inherited attributes for something real, not as an exercise: a bare D has no octave, ^5 has no pitch, and a note written without a length has no duration until the context supplies one.

octave          so a bare 'D' knows which D
duration        so 'F4' with no /8 has a length

stretch n/d     accumulated by every enclosing slow/fast

Synthesised (flow up)

Module 4 — Three-address code

The generator is deliberately naive: every note emits the same six-instruction pattern even when the transposition is 0 and the stretch is 1/1. That is the standard front-end / middle-end contract — and it is what gives Module 5 something to do.

Backpatching. repeat n of X needs a jump out of the loop before the label it jumps to exists. The generator emits the jump with an empty target, keeps its index in a list (makelist), and fills it in when the label is finally generated (backpatch) — the textbook technique, visible in irgen.py: _Repeat.

Security checking of virtual machine code

The syllabus lists “implementation of a naive code generator for a virtual machine, security checking of virtual machine code”. Before the VM executes anything, the generated code is checked by abstract interpretation over the control-flow graph. These are the same five families of check a JVM bytecode verifier, a WebAssembly validator or the eBPF verifier performs.

1. every jump target exists  ·  2. every CALL matches the callee's arity and enough PARAMs were pushed on every path  ·  3. parallel-block nesting agrees at every merge point (the same shape of check as operand-stack depth agreement)  ·  4. no local is read on a path where it was never written (a forward “definitely assigned” analysis, meet = intersection)  ·  5. every procedure ends in RET and cannot fall off the end.
The VM is also sandboxed at run time: step, frame-depth and event limits.
